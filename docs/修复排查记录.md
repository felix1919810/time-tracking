# 稳定性与显示速度排查（2026-09-06）

范围：当前中文网站 `frontend/` 与对应 SCF 后端 `frontend/api-deploy/`。依据源码检查和本地测试；未连接真实用户数据、未部署。早期 Python/Node 后端不作为本轮运行入口。

更新：以上为首轮修复时状态；2026-09-06 已进入在线验收部署，见文末发布记录。

## 已确认的问题与处理顺序

1. **计时一致性（高）**：停止请求完成前清空状态，失败也不恢复；快速开始/停止有竞态；恢复信任旧缓存，cookie 的 ID 与服务端记录混用；退出账号未清空计时状态。先建立明确的开始、停止、恢复状态与失败重试行为。
2. **工时完整性（高）**：五个页面只读前 500 条，接口丢弃下一页游标；会导致历史记录缺失和统计偏小。前后端一起补分页。
3. **缓存与视图同步（高）**：周视图把已筛选的记录覆盖全量缓存；日视图没有计时事件监听；编辑、删除、跨视图切换的缓存失效不一致。统一记录源，按记录 ID 更新。
4. **身份匹配（中）**：有的页面只匹配姓名，有的匹配用户名；修改姓名后记录可能消失。新记录使用用户名，显示兼容已有姓名记录。历史重名/改名数据需要独立迁移，不能无依据批量改写。
5. **异常与输入（中）**：HTTP 500 丢失后端错误；缓存 JSON 损坏可导致白屏；编辑未校验时间范围；运行中的任务被编辑成已结束但计时栏仍在运行。
6. **重复请求与首屏（中）**：所有页面和 Chart.js 同步打包；分类重复请求；条目请求后才开始部分元数据请求；切周重复全量请求；图表卸载未销毁。按需加载页面、合并请求、并行加载和清理图表。
7. **统计口径（待单独统一）**：跨午夜记录全部归于开始日；仪表盘/报表静默丢弃超过 24 小时的记录；进行中时长更新不一致。先避免 NaN 和静默漏算，跨日分摊需要同步处理图表、明细、导出，不能只改一个数值。
8. **发布入口（中）**：GitHub Pages 子路径与 COS 根路径混用；多份历史产物与入口并存。构建路径显式可配置，记录部署方式。

## 需要独立完成的服务端安全改造

- 登录只返回用户信息，缺少可信的服务端会话；多个读写接口信任客户端传来的用户/角色或记录 ID。前端筛选不能保障权限。
- 用户密码按明文字段匹配；应用密钥存在源码默认值。需要迁移密码存储、部署端注入密钥并轮换已入库的凭证。
- 飞书绑定、授权 state 校验和接口鉴权需要一起收口。

这些是已确认的现有设计问题。本轮前端性能与计时修复不能宣称解决了服务端权限；迁移必须配套测试账号与部署配置，避免现有用户无法登录。不会自动发布或变更真实工时数据。

## 验证方式

使用本地模拟接口验证失败、延迟、超过 500 条、换账号和视图切换；使用 Node 内置测试运行器测试公共逻辑；执行生产构建并比较按需加载前后的包大小。真实 SCF 延迟与线上飞书登录仍需部署后验证。

## 本轮已完成

- 抽出共享计时控制器：开始防连点、停止等待真实 ID、失败保留计时供重试、恢复以服务端为准、账号切换隔离迟到响应；恢复失败时先核对状态再允许开始。
- SCF 返回分页游标；前端加载全部页、去重并检测缺失/重复游标。分页失败保留原数据并显示可重试提示。
- 周、日、列表共用记录源；按 ID 更新、删除和回滚，操作某成员不会覆盖其他人的记录。加载期间产生的新计时会与响应合并。
- 新工时使用用户名；成员及团队筛选兼容旧姓名记录；前端按角色约束筛选范围（不等同于服务端鉴权）。
- 编辑校验有效时间范围；未停止记录先停止再编辑/删除；服务端重复停止保持原结束时间。
- HTTP 保留错误原因、增加超时；并发请求合并，短时缓存，写入及换账号清除缓存；元数据与条目并行加载；切换周直接在内存过滤。
- 六个页面按需加载；Chart.js 延后至图表页下载；图表卸载时释放实例。
- 修复坏 JSON/过期页面名造成的白屏、侧栏收起后工具栏错位、日历模式标签不同步。
- 统一时长计算，避免 NaN 和超过 24 小时静默清零；以分钟频率更新进行中统计，避免每秒重绘图表。
- 报表详情和 CSV 正确读取 `notes`；CSV 各列统一引号转义，不先把分钟取整再导出。
- 构建前缀可配置；补充当前入口、测试及 COS/GitHub Pages 构建说明。
