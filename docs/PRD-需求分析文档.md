## 1. 项目背景

### 1.1 问题现状

当前团队/个人工时管理存在以下痛点：

1. **工具分散**：计时用手机 App，报表用 Excel，沟通用飞书——数据割裂，复盘成本高
2. **现有工具不适配**：Toggl Track 功能完善但无飞书原生集成，中文体验和团队协作弱
3. **工时数据沉睡**：计时数据停留在个人手里，无法聚合为团队/项目维度的可视化报表
4. **提醒缺失**：忘记停止计时器、项目工时超额无人预警，导致数据失真

### 1.2 项目目标

在飞书生态内复现 Toggl Track 的核心能力：

- **计时**：一键开始/停止，支持手动补录
- **数据组织**：项目/客户/标签三层结构，支持归档
- **报表分析**：按日/周/月/项目/标签多维度聚合与可视化
- **智能提醒**：未停止计时器提醒、工时超额预警、日报周报自动推送
- **飞书集成**：多维表格存储、消息机器人交互、工作台入口

### 1.3 成功标准

| 指标 | 目标 |
|---|---|
| 核心流程可用 | 用户能在飞书内完成"创建项目→计时→查看周报→收到提醒"全链路 |
| 数据准确率 | 计时器停止后时长计算误差 ≤ 1 秒 |
| 报表覆盖率 | 支持按项目/标签/日期/用户 4 个维度的聚合 |
| 提醒触达率 | 定时任务触发后 5 分钟内消息送达 |
| 交付时间 | 4 周内完成 MVP 并可演示 |

## 2. 用户角色与场景

### 2.1 用户角色定义

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| **个人贡献者（IC）** | 日常记录自己工时的员工 | 快速计时、看自己的日报/周报 |
| **项目经理（PM）** | 管理项目、监控工时预算 | 项目工时汇总、超额预警、团队分配 |
| **团队管理员** | 管理客户/项目/标签、配置提醒 | 数据归档、权限管理、报表导出 |

### 2.2 典型用户故事

#### US-1：快速开始计时（IC）
> 作为一名开发者，我希望在飞书里一键开始计时并关联到当前项目，这样我不用切换 App 就能记录工时。

**验收标准**：
- 从飞书工作台打开应用 → 点"开始计时" → 选择项目 → 计时开始，全过程 ≤ 3 次点击
- 计时进行中，应用首页显示当前条目描述和已计时时长
- 同一用户同一时刻最多 1 个进行中条目（开始新计时自动停止旧的）

#### US-2：忘记停止计时器（IC）
> 作为一名经常忘记停止计时的员工，我希望系统在计时运行超过一定时长后提醒我，避免数据失真。

**验收标准**：
- 计时器运行超过 8 小时，系统每小时检查并推送飞书消息卡片提醒
- 提醒卡片包含条目描述、开始时间、已运行时长
- 卡片上有"停止计时"按钮，点击即停止

#### US-3：查看本周工时分布（IC）
> 作为一名需要复盘时间花费的员工，我希望看到本周每天每个项目的工时柱状图。

**验收标准**：
- 报表页默认展示本周（周一到周日）数据
- 日期维度：柱状图，X 轴为日期，Y 轴为小时数
- 项目维度：饼图，展示各项目占比
- 支持切换日/周/月视图

#### US-4：项目工时超额预警（PM）
> 作为一名项目经理，我希望当项目实际工时超过预估工时时收到预警，及时调整计划。

**验收标准**：
- 项目设置预估工时（小时）
- 每天 10:00 自动检测所有活跃项目
- 实际工时 > 预估工时 → 推送红色预警卡片到项目经理私聊
- 卡片包含项目名、预估/实际工时、超额时长

#### US-5：导出工时报表（管理员）
> 作为一名需要做月度工时汇报的管理员，我希望能导出指定时间范围的工时 CSV。

**验收标准**：
- 选择起止日期 → 点击导出 → 下载 CSV
- CSV 列：日期、描述、项目、标签、开始时间、结束时间、时长（秒）、是否计费、用户
- 编码 UTF-8，Excel 可直接打开

#### US-6：机器人快捷操作（IC）
> 作为一名不想打开应用的员工，我希望直接在飞书聊天里 @机器人 发指令完成计时。

**验收标准**：
- 支持指令：`开始 <描述>`、`停止`、`当前`、`日报`、`周报`、`帮助`
- 机器人响应时间 ≤ 2 秒
- 指令识别容错（大小写、多余空格）

### 3.2 F1 计时功能

#### F1.1 开始计时

| 项 | 内容 |
|---|---|
| **触发方式** | 前端按钮 / 机器人指令 `开始 <描述>` |
| **输入参数** | 用户 ID、描述（可选）、项目 ID（可选）、标签（可选）、是否计费（默认否）、开始时间（默认当前） |
| **业务规则** | ① 同一用户已有进行中条目时，自动停止旧的 ② 新建条目状态为 `running`，时长字段为 0 ③ 开始时间写入多维表格日期字段（毫秒时间戳） |
| **输出** | 新条目 record_id |
| **异常处理** | 多维表格写入失败 → 返回错误码 + 日志记录 |

#### F1.2 停止计时

| 项 | 内容 |
|---|---|
| **触发方式** | 前端按钮 / 机器人指令 `停止` / 卡片按钮回调 |
| **输入参数** | record_id、停止时间（默认当前） |
| **业务规则** | ① 读取条目开始时间 ② 计算 `duration = stop - start`（秒） ③ 写入停止时间、时长、状态改为 `stopped` ④ 停止时间不能早于开始时间（容错：取开始时间） |
| **输出** | 条目 record_id、开始时间、停止时间、时长（秒） |
| **并发处理** | 同一条目被重复停止请求 → 第二次返回当前状态，不重复计算 |

#### F1.3 查看当前计时

| 项 | 内容 |
|---|---|
| **触发方式** | 前端首页 / 机器人指令 `当前` |
| **输入参数** | 用户 ID |
| **业务规则** | 查询 `状态 = running AND 用户 = user_id` 的条目 |
| **输出** | 条目描述、开始时间、已计时时长（实时计算） |
| **边界** | 无进行中条目 → 返回空 |

#### F1.4 手动添加工时

| 项 | 内容 |
|---|---|
| **触发方式** | 前端"补录"表单 |
| **输入参数** | 用户 ID、描述、项目 ID、标签、是否计费、开始时间、结束时间 |
| **业务规则** | ① 结束时间必须晚于开始时间 ② 直接创建 `stopped` 状态条目 ③ 自动计算时长 |
| **输出** | record_id、时长（秒） |

#### F1.5 编辑条目时间

| 项 | 内容 |
|---|---|
| **触发方式** | 前端条目详情页"编辑" |
| **输入参数** | record_id、新开始时间（可选）、新结束时间（可选） |
| **业务规则** | 修改时间后重新计算 duration |
| **输出** | 新时长（秒） |

#### F1.6 删除条目

| 项 | 内容 |
|---|---|
| **触发方式** | 前端条目列表"删除" |
| **业务规则** | MVP 用硬删除；迭代 2 改为软删除（标记 `archived`） |
| **权限** | 条目所属用户或管理员可删 |

### 3.3 F2 数据组织

#### F2.1 项目管理

| 操作 | 说明 |
|---|---|
| 创建项目 | 名称、客户、颜色、是否计费、预估工时 |
| 列出项目 | 支持 `?status=active\|archived\|all` |
| 更新项目 | 部分字段更新 |
| 归档项目 | 状态改为 `archived`，不在下拉列表显示 |
| 取消归档 | 状态改回 `active` |
| 删除项目 | 硬删除，关联的时间条目保留但项目字段置空 |

#### F2.2 客户管理

| 操作 | 说明 |
|---|---|
| 创建客户 | 名称（唯一）、联系人、邮箱 |
| 列出客户 | 支持 active/archived/all 过滤 |
| 归档客户 | 关联项目一并隐藏 |

#### F2.3 标签管理

| 操作 | 说明 |
|---|---|
| 创建标签 | 名称（唯一） |
| 列出标签 | 全量返回 |
| 删除标签 | 已使用该标签的条目保留标签文本 |

#### F2.4 时间条目管理

| 操作 | 说明 |
|---|---|
| 创建条目 | 手动补录，直接 stopped 状态 |
| 列出条目 | 支持按用户/项目/时间范围过滤 |
| 获取单条 | 用于详情页 |
| 更新条目 | 修改描述/项目/标签/计费/时间 |
| 删除条目 | 硬删除 |

#### F2.5 计费标记

- 条目级 `是否计费` 字段，默认继承所属项目的计费设置
- 创建条目时可手动覆盖
- 报表聚合时区分计费/非计费工时

### 3.4 F3 报表与分析

#### F3.1 工时汇总

| 维度 | 时间范围 | 触发 |
|---|---|---|
| 日报 | 当天 00:00-23:59 | 每天 18:00 自动推送 / 手动触发 |
| 周报 | 本周一到周日 | 每周一 09:00 自动推送 / 手动触发 |
| 月报 | 本月 1 日到最后一天 | 手动触发 |
| 自定义 | start_ms 到 end_ms | 前端选择日期范围 |

#### F3.2-F3.4 聚合维度

| 维度 | 输出字段 | 排序 |
|---|---|---|
| 按项目 | project_id, project_name, total_sec, count | total_sec 降序 |
| 按标签 | tag_name, total_sec, count | total_sec 降序 |
| 按日期 | date(YYYY-MM-DD), total_sec, count | date 升序 |

#### F3.5 数据导出

- 格式：CSV，UTF-8 编码
- 列：日期、描述、项目、标签、开始时间、结束时间、时长（秒）、是否计费、用户
- 文件名：`time_entries_{start}_{end}.csv`
- 响应头：`Content-Disposition: attachment; filename=...`

#### F3.6 可视化图表

| 图表类型 | 数据源 | 用途 |
|---|---|---|
| 柱状图 | by_date | 每日工时趋势 |
| 饼图 | by_project | 项目工时占比 |
| 堆叠柱状图 | by_date × by_project | 每日各项目工时分布 |
| 甘特图 | time_entries 列表 | 时间条目时间轴展示 |

#### F3.7 团队工作量看板（迭代 1）

- 展示团队成员本周工时排行
- 按项目维度展示人员投入分布
- 需要通讯录权限获取部门/人员信息

### 3.5 F4 智能提醒

#### F4.1 未停止计时器提醒

| 项 | 内容 |
|---|---|
| **触发频率** | 每小时 :05 执行 |
| **检测逻辑** | 扫描所有 `状态 = running` 的条目，计算运行时长 |
| **提醒阈值** | 运行时长 ≥ 8 小时 |
| **推送方式** | 飞书消息卡片到条目所属用户私聊 |
| **卡片内容** | 条目描述、开始时间、已运行时长、"停止计时"按钮 |

#### F4.2 工时超额预警

| 项 | 内容 |
|---|---|
| **触发频率** | 每天 10:00 执行 |
| **检测逻辑** | 遍历所有 `active` 项目，对比实际工时与 `预估工时` |
| **提醒条件** | 实际工时 > 预估工时 |
| **推送方式** | 红色预警卡片到项目经理私聊 |
| **卡片内容** | 项目名、预估工时、实际工时、超额时长 |

#### F4.3 每日总结推送

| 项 | 内容 |
|---|---|
| **触发时间** | 每天 18:00 |
| **推送内容** | 当日总工时、条目数、各项目工时明细 |
| **推送方式** | 蓝色消息卡片到群聊 |
| **卡片字段** | 总工时、条目数、项目明细（最多 5 个） |

#### F4.4 每周总结推送

| 项 | 内容 |
|---|---|
| **触发时间** | 每周一 09:00 |
| **推送内容** | 上周总工时、每日工时分布 |
| **推送方式** | 绿色消息卡片到群聊 |
| **卡片字段** | 周期、总工时、每日工时列表 |

#### F4.5 日历事件自动导入（迭代 2）

- 接入飞书日历 v4 API
- 监听日程创建事件，自动生成对应的时间条目
- 需要日历读写权限

### 3.6 F5 飞书集成

#### F5.1 多维表格存储

4 张数据表：clients（客户）、projects（项目）、tags（标签）、time_entries（时间条目）。详细字段定义见《技术设计文档》第 2 章。

#### F5.2 消息机器人交互

**指令列表**：

| 指令 | 别名 | 功能 |
|---|---|---|
| `开始 <描述>` | `start` | 开始计时 |
| `停止` | `stop` | 停止当前计时 |
| `当前` | `current` | 查看正在计时的条目 |
| `日报` | `daily` | 推送今日工时报表 |
| `周报` | `weekly` | 推送本周工时报表 |
| `帮助` | `help` | 显示指令列表 |

**消息卡片交互**：
- 日报/周报卡片底部可加"查看完整报表"按钮
- 未停止计时器提醒卡片加"停止计时"按钮
- 按钮回调通过 `card.action.trigger` 事件接收

#### F5.3 事件订阅回调

| 事件 | Event Type | 用途 |
|---|---|---|
| 接收消息 | `im.message.receive_v1` | 机器人指令处理 |
| 卡片按钮点击 | `card.action.trigger` | 卡片交互回调 |

**回调地址**：`https://your-domain/api/lark/webhook`

**URL 验证**：飞书首次配置回调时会发送 `{"type":"url_verification","challenge":"..."}`，需原样返回 challenge。

#### F5.4 网页应用工作台入口

- 在飞书开放平台配置网页应用
- 首页 URL 填应用前端地址
- 用户从飞书工作台点击应用图标进入
- 需要处理飞书免登（jsapi 鉴权）

#### F5.5 多维表格仪表盘

- 利用多维表格原生仪表盘能力做辅助可视化
- 配置：按项目分组的工时柱状图、按标签分组的饼图
- 优势：零开发成本，数据实时同步

#### F5.6 小程序原生前端（迭代 3）

- 用飞书小程序开发工具（opdev）开发
- 优势：原生体验、离线可用
- 劣势：需走发布审批流程

## 4. 非功能需求

### 4.1 性能

| 指标 | 要求 |
|---|---|
| API 响应时间 | P95 ≤ 500ms（不含飞书 API 调用耗时） |
| 计时器启停 | 用户感知延迟 ≤ 1 秒 |
| 报表查询 | 单次聚合查询 ≤ 3 秒（500 条以内） |
| 并发支持 | MVP 单实例支持 50 并发 |

### 4.2 可靠性

| 项 | 要求 |
|---|---|
| 飞书 API 失败重试 | 自动重试 3 次，间隔指数退避 |
| 定时任务容错 | 单次任务失败不影响下次执行，记录错误日志 |
| 数据一致性 | 计时器停止操作幂等，重复停止不产生负时长 |
| 服务可用性 | MVP 不做高可用，单实例部署 |

### 4.3 安全

| 项 | 要求 |
|---|---|
| 飞书凭证存储 | App Secret 不进代码仓库，通过 .env 环境变量注入 |
| 事件回调验签 | 校验请求来源 token，防止伪造回调 |
| 用户鉴权 | 前端通过飞书 jsapi 获取 user identity，后端校验 |
| 数据隔离 | MVP 单租户，多租户留待迭代 |

### 4.4 可维护性

| 项 | 要求 |
|---|---|
| 代码结构 | 分层架构：路由层 / 服务层 / 数据访问层 |
| 日志 | 关键操作（计时启停、报表生成、消息推送）记录结构化日志 |
| 配置管理 | 所有可变参数通过环境变量配置，不硬编码 |
| 文档 | API 接口通过 FastAPI 自动生成 OpenAPI 文档 |

## 5. 验收标准

### 5.1 功能验收

| 编号 | 验收项 | 验收方法 |
|---|---|---|
| AC-1 | 用户能在飞书工作台打开应用并开始计时 | 手动操作，条目写入多维表格 |
| AC-2 | 停止计时后时长正确（误差 ≤ 1 秒） | 开始计时 → 等待 60 秒 → 停止 → 时长应为 60 ± 1 秒 |
| AC-3 | 能创建/归档/删除项目 | CRUD 操作后多维表格数据一致 |
| AC-4 | 周报包含按项目/标签/日期的聚合数据 | 与多维表格手动汇总结果对比 |
| AC-5 | 能导出 CSV 并在 Excel 打开 | 导出后检查列和编码 |
| AC-6 | 每天 18:00 自动推送日报卡片 | 修改定时任务到近期时间，验证推送 |
| AC-7 | 项目工时超额时收到红色预警卡片 | 设置低预估工时，触发检测 |
| AC-8 | @机器人发"开始 编码"能开始计时 | 在飞书群聊里 @机器人发指令 |
| AC-9 | 机器人发"停止"能停止当前计时 | 同上 |
| AC-10 | 计时器运行超 8 小时收到提醒 | 设置低阈值测试 |
