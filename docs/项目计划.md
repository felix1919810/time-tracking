## 1. 里程碑

| 里程碑 | 时间 | 交付物 | 验收标准 |
|---|---|---|---|
| **M1：环境搭建** | W1 第 1-3 天 | 飞书应用创建、多维表格建表、后端跑通 | 后端能往多维表格写入测试条目 |
| **M2：核心计时** | W1 第 4-5 天 + W2 第 1-2 天 | 计时器启停、条目 CRUD、前端计时器 UI | 在飞书里点"开始计时"能写入条目 |
| **M3：数据组织** | W2 第 3-5 天 | 项目/客户/标签管理界面、多维表格仪表盘 | 能创建项目并关联到计时条目 |
| **M4：报表分析** | W3 第 1-3 天 | 报表聚合、可视化图表、CSV 导出 | 看到本周工时柱状图和项目占比饼图 |
| **M5：智能提醒** | W3 第 4-5 天 | 定时任务、消息卡片推送、超额预警 | 飞书群里收到日报卡片，超额项目收到预警 |
| **M6：飞书集成** | W4 第 1-3 天 | 机器人指令、事件回调、工作台入口 | @机器人发"开始 编码"能开始计时 |
| **M7：测试交付** | W4 第 4-5 天 | 端到端测试、Bug 修复、演示文档 | 完整演示"创建项目→计时→看周报→收提醒" |

## 2. 周计划详述

### 2.1 W1（第 1 周）：环境搭建 + 核心计时启动

| 天 | 任务 | 产出 |
|---|---|---|
| Day 1 | 飞书开放平台创建自建应用，开通权限，提交审批 | 应用 App ID / App Secret |
| Day 1 | 创建飞书多维表格，按数据模型建 4 张表 | 多维表格 app_token + 4 个 table_id |
| Day 2 | 后端项目初始化，飞书 SDK 接入，配置 .env | 后端能启动并调用飞书 API |
| Day 2 | 编写自动建表脚本（可选，验证字段类型） | 建表脚本 |
| Day 3 | 多维表格数据访问层（bitable_repo）实现 + 测试 | 能 CRUD 多维表格记录 |
| Day 3 | 计时器核心服务（timer_service）实现 | start_timer / stop_timer 函数 |
| Day 4 | 计时器 REST 路由（timer.py）实现 | /api/timer/start 等接口可用 |
| Day 4 | 时间条目 CRUD 路由（entries.py）实现 | /api/entries 接口可用 |
| Day 5 | 前端项目初始化（Vue 3 + Vite） | 前端能启动 |
| Day 5 | 前端计时器组件开发（开始/停止按钮 + 当前计时显示） | 能调用后端 API 开始计时 |

**W1 验收**：
- 后端 /api/timer/start 调用成功，多维表格出现新条目
- 前端能显示"正在计时：编写文档 已计时 0:05:30"

### 2.2 W2（第 2 周）：核心计时完成 + 数据组织

| 天 | 任务 | 产出 |
|---|---|---|
| Day 6 | 前端项目选择器 + 标签选择器开发 | 开始计时时能选项目和标签 |
| Day 6 | 前端时间条目列表页开发 | 能看到历史条目列表 |
| Day 7 | 前端时间条目编辑/删除功能 | 能修改条目时间和描述 |
| Day 7 | 前端手动补录工时表单 | 能补录一段已完成的工时 |
| Day 8 | 后端项目/客户/标签 CRUD 路由（projects.py） | /api/projects 等接口可用 |
| Day 8 | 前端项目管理界面（创建/归档/删除） | 能在界面上管理项目 |
| Day 9 | 前端标签管理界面 + 客户管理界面 | 能管理标签和客户 |
| Day 9 | 多维表格仪表盘配置（按项目柱状图、按标签饼图） | 多维表格里有可视化图表 |
| Day 10 | 计费标记功能（条目级 + 项目级继承） | 计费标记能正确继承和覆盖 |

**W2 验收**：
- 能在界面上创建项目、开始计时关联项目、停止计时
- 时间条目列表能正确显示，能编辑和删除
- 多维表格仪表盘能看到工时分布图

### 2.3 W3（第 3 周）：报表分析 + 智能提醒

| 天 | 任务 | 产出 |
|---|---|---|
| Day 11 | 后端报表服务（report_service.py）实现 | 聚合函数可用 |
| Day 11 | 后端报表路由（reports.py）实现 | /api/reports/weekly 等接口可用 |
| Day 12 | 前端报表页开发（日/周/月切换 + 柱状图 + 饼图） | 能看到本周工时柱状图 |
| Day 12 | 前端报表页甘特图组件开发 | 能看到时间条目甘特图 |
| Day 13 | 后端 CSV 导出功能实现 | /api/reports/export 接口可用 |
| Day 13 | 前端导出按钮 + 下载逻辑 | 能点击导出 CSV |
| Day 14 | 后端定时任务调度器（scheduler.py）实现 | APScheduler 能启动 |
| Day 14 | 后端消息推送服务（notify_service.py）实现 | 能发送飞书消息卡片 |
| Day 15 | 智能提醒四个任务实现并测试 | 未停止提醒/超额预警/日报/周报 |

**W3 验收**：
- 报表页能看到本周每日工时柱状图和项目占比饼图
- 能导出 CSV 并在 Excel 打开
- 修改定时任务到近期时间，飞书群收到日报卡片

### 2.4 W4（第 4 周）：飞书集成 + 测试交付

| 天 | 任务 | 产出 |
|---|---|---|
| Day 16 | 飞书消息机器人指令处理实现 | @机器人发"开始 编码"能开始计时 |
| Day 16 | 飞书事件订阅回调配置 + 测试 | webhook 能正确接收和处理事件 |
| Day 17 | 飞书消息卡片交互（按钮回调）实现 | 卡片上的"停止计时"按钮能停止计时 |
| Day 17 | 飞书网页应用工作台入口配置 | 能从飞书工作台点开应用 |
| Day 18 | 端到端测试：创建项目→计时→看周报→收提醒 | 测试报告 |
| Day 18 | Bug 修复 | 修复清单 |
| Day 19 | 演示文档编写 | 演示 PPT / 截图集 |
| Day 19 | 部署文档编写 | 部署指南 |
| Day 20 | 最终演示 + 交付 | 演示完成，代码交付 |

**W4 验收**：
- @机器人发"开始 编码"能开始计时，发"停止"能停止
- 能从飞书工作台点开应用，完成完整计时流程
- 端到端演示"创建项目→计时→看周报→收提醒"成功

## 3. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 飞书多维表格 API 行为与文档不符 | 高 | 中 | W1 尽早实测每个字段类型的读写行为，记录踩坑笔记 |
| 飞书应用审批流程耗时 | 中 | 高 | W1 第 1 天就提交应用创建和权限申请，并行开发后端 |
| 消息卡片模板渲染异常 | 中 | 中 | 用飞书卡片搭建工具预先验证模板结构 |
| 定时任务时区配置错误 | 低 | 中 | 明确配置 `Asia/Shanghai` 时区，日志记录触发时间 |
| 前端 H5 在飞书客户端里适配问题 | 中 | 中 | W2 尽早在飞书客户端里验证 H5 渲染和 jsapi 鉴权 |
| 时间预估不足导致延期 | 中 | 高 | W2 末做进度检查，若延期则砍 F3.7 团队看板（迭代 1 项） |
